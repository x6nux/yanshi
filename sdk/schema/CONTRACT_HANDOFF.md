# V14 Contract Handoff (D2 → D1)

D2 currently consumes `sdk/schema/v1/agent-api.schema.json`, a provisional
mirror of `internal/api/v1/types.go`. D1 owns the canonical wire shapes; the
TS mirror at `sdk/ts/v1.ts` is regenerated by `go run ./cmd/api-schema`.

When D1 publishes the canonical schema (e.g. by expanding
`internal/api/v1/schema.go` to cover params/response shapes and serving it at
`GET /api/v1/schema/agent-v1.json`), replace this file using the following
checklist. Until then, the provisional flag stays.

## Replacement checklist

1. **Diff the version envelope.** Confirm `Version` is still `"v1"`,
   `X-Yanshi-API-Version` header is still emitted on every response, and
   the in-body `version` field is still required.
2. **Diff the resource routes.** D2 assumes:
   - `POST /api/v1/thread/start`     -> ThreadStartResponse
   - `POST /api/v1/thread/resume`    -> ThreadResumeResponse (body: threadId)
   - `POST /api/v1/thread/interrupt` -> InterruptResponse   (body: threadId, turnId?)
   - `POST /api/v1/turn/start`       -> SSE stream (event: turn, then event: item*)
   - `GET  /api/v1/schema/agent-v1.json` -> JSON Schema document
3. **Diff item identity.** D2 keys recovery on `Item.sequence` (monotonic int
   per thread, >= 1). If D1 adds `cursor` or `eventId` strings, the SDK's
   transport + the IDE's `recovery.ts` need a coordinated update; both
   currently expect a single monotonic integer.
4. **Diff item types.** D1 emits: `turn.started`, `message.delta`,
   `reasoning.delta`, `tool.call`, `tool.result`, `tool.progress`,
   `structured.result`, `turn.error`, `turn.completed`. Unknown server values
   arrive as `event.<legacyType>`. If D1 collapses or renames any of these,
   update `KNOWN_ITEM_TYPES` in both `sdk/ts/src/transport.ts` and
   `sdk/python/src/yanshi_sdk/generated.py`.
5. **Diff IDE context.** D2 attaches `ContextItem[]` (selection/openFile) to
   `TurnStartParams.context` — a field D1 does not yet read (it ignores
   unknown fields). If D1 adds canonical ContextItem support, the cast in
   `sdk/ts/src/client.ts` and the body builder in
   `sdk/python/src/yanshi_sdk/client.py` are no-ops.
6. **Diff fileChange.** D2-provisional `FileChange` (path/before/after/
   unifiedDiff) is attached to `Item.fileChange`. D1 does not yet emit
   this; the IDE diff renderer degrades gracefully. When D1 starts emitting
   fileChange items, `KNOWN_ITEM_TYPES` may need a `fileChange` entry and
   `output.ts` may need a new case.
7. **Diff auth policy.** D2 only sends `Authorization: Bearer <token>` via
   the SDK's transport headers. The token never enters URLs, event payloads,
   context, or logs. The VS Code extension stores it in SecretStorage only.
8. **Re-run the contract matrix.**
   ```sh
   npm --prefix sdk/ts run test
   python -m pytest sdk/python/tests -q
   python -m yanshi_sdk.contract
   ```
   All must pass on the new canonical schema before the provisional flag
   comes off.
9. **Regenerate the canonical TypeScript mirror.** `go run ./cmd/api-schema
   -out sdk/ts/v1.ts` produces the canonical types; D2's `src/generated.ts`
   re-exports them, so a regenerate picks up new fields automatically.

## Known gaps (call-outs that need a D1 decision)

- **No cursor-based stream replay.** D1's `/api/v1/turn/start` returns one
  SSE response that cannot be resumed mid-flight; on disconnect the IDE must
  call `thread/resume` (which returns the in-memory item snapshot) and either
  accept that the active turn's stream is lost or wait for the turn to
  complete. The `runWithRecovery` state machine is forward-looking.
- **No WebSocket transport.** D1 has SSE + JSON-RPC-over-stdio; the SDK's
  WS path is forward-looking and currently raises `ProtocolError` in Python
  and uses the same shape as the JSON-RPC `item/updated` notification in TS.
- **No minor version string.** D1 emits exactly `"v1"`. The SDK accepts any
  `v1.<minor>` string for additive compatibility; if D1 never intends to
  publish a minor bump, the version check can be tightened.
- **Item.id pattern.** D1 emits `"item-<sequence>"` (e.g. `item-1`,
  `item-42`). The SDK's Pydantic model enforces `^item-[1-9][0-9]*$`; if D1
  changes the id format, update both `sdk/python/src/yanshi_sdk/generated.py`
  and `sdk/ts/src/validators.ts`.

## Version policy

- Accept: `"v1"`, `"v1.x"` (any minor). All other values fail closed with
  `ApiVersionError`.
- Unknown response fields: tolerated (`extra="allow"` in Pydantic,
  index signature in TS).
- Unknown item types: preserved as `event.<legacyType>` (or the original
  string), not silently dropped. Rendered by the IDE as `[event] ignored
  <type> at sequence <n>`.
- Duplicate item ids: SDK delivers as-is; the IDE recovery layer
  de-duplicates via `seen` Set in `runWithRecovery`.
