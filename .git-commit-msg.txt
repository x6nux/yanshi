fix(ci,tuidbg,yanshi): 三平台 CI 全绿的最后一批环境/平台适配

race / coverage / test (windows) 首轮完整跑完暴露的四组问题：

1. ci.yml（ubuntu 三 leg）：ubuntu-24.04 镜像默认开启 AppArmor 的
   unprivileged-userns 限制，bwrap 装了也无法建 sandbox（exit 1），
   sandbox 探测逐子进程走降级回退（landlock helper 重试 + managed
   proxy 反复拉起），-race 下累计越过包级 10m deadline——race 与
   coverage 两 job 皆因此超时。test/race/coverage 三 leg 统一加
   sysctl kernel.apparmor_restrict_unprivileged_userns=0（单租户
   runner VM，社区标准解法）。

2. cmd/tuidbg（windows）：布局常量 charW=17/ascent=26 按 Menlo 写死；
   Windows 主字体 Consolas 同档位实测步进 15、Ascent 21（Height 恰
   好同为 33）。常量改 var + GOOS 分支，平台内恒定不变，「图片尺寸
   只取决于网格」的设计不变。

3. cmd/tuidbg（windows 测试）：Consolas 的 ─ 墨迹不满步进（字体事
   实），制表符跨格连续性断言在 Menlo 上成立、在 Consolas 上必挂；
   该断言的意图是抓实现错误的规律性缝，故 Windows skip 并注明原因。

4. internal/agent/orchestrator（windows 测试）：hook 改写目标的
   /etc/cron.d 是 POSIX 专属受保护路径，Windows 无 /etc，改写后落
   在 worktree 内被正确允许——断言一个在该平台无意义的拒绝。
   Windows skip 并注明。

cmd/yanshi goalwiring 的 TestAbsWorkdirIsCleaned 期望值同前法改为
filepath.Clean 推导（884b1fa 漏网的同类）。
