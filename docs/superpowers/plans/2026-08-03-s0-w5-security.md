# S0/W5 安全底座 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 堵上 execpolicy 的 deny 规则绕过，给持久审批加上真正会过期的过期时间，把「伪装成强制的网络黑洞」换成真实的受管代理，并修复统一脱敏链路里那处让 `SafeLogger` 全瞎的别名断裂。

**Architecture:** 四条互不相交的链路：① `internal/execpolicy` 的 flag 归一化；② `internal/approval` 的 TTL；③ `internal/netpolicy` + `internal/shell` 的代理启动与 CONNECT；④ `internal/bootstrap` 的 redactor 注册顺序。**只有 ③ 改变对外可见的安全姿态**，需要新 ADR。

**Tech Stack:** Go 1.26.4，`zalando/go-keyring`，AES-256-GCM 文件后端。

## 四条裁定

**裁定 1 — S06 只改 `containsAny` 的 flag 归一化，不动 `hasPrefix` / `normalizeProgram`。**
严格限定在 flag 归一化时，该改动**只让 deny 匹配更多形式 = 收紧**。一旦顺手动了另两个函数就会**放宽**。

**必须双向测试**：三种绕过形式全部 `HardDeny`；**同时**断言普通 `go test ./...`、`go build`、`go test -run X` 仍 `Allow` —— 防止过度拒绝把 deny 规则变成全局封杀，**那正是 `policy.go:13-18` 记录的原始回归**。

**裁定 2 — S07 加 `ExpiresAt`（纯收紧），但**不实现**前缀匹配档。**
验收里「前缀规则有绕过回归测试」用一条**钉死精确相等语义**的测试来满足（证明不存在前缀放宽面），**而不是新增放宽能力**。

> 若坚持实现前缀档：必须有测试证明 `Prefix=["test"]` 的规则**不会**准入 `go test -tags=e2e_real ...`，即前缀规则不得跨过 execpolicy 的 deny。**本计划建议不做。**

**裁定 3 — S09 采用 Option B，且 CONNECT 是先决条件不是可选项。**

为什么不选 Option A（建在 `sandbox.Sandbox.Prepare` 上）：四个 adapter 的 `Prepare` **全是文档化 no-op**，`Effective` 恒 `DegradedHostGuard` —— **写在这上面的东西没有可观测行为可断言，测试写不出来**，且 S1 必定重做。

为什么现在就该修：**当前真正的缺陷不是「没有沙箱」，而是接线谎报。** 代理写好了却从不启动，fallback URL `http://127.0.0.1:0` 是个**伪装成强制的黑洞** —— 它让 HTTP 客户端型子进程连不上网，看起来像在执行策略，实际既不放行合法流量也不产生任何决策记录。**无论 S1 怎么做，这个都得修。**

⚠️ **CONNECT 必须一并做**：`Proxy` 明确拒绝 CONNECT，一旦真启动代理，所有需 HTTPS 的子进程会立刻全断。CONNECT 的策略化实现同样**不需要沙箱**（从 CONNECT 请求行取目标 host 跑 `CheckHost`，通过后盲隧道，**不做 MITM**）。

**裁定 4 — S10 修复 `MergeRedactors` 的别名语义（纯收紧）。**
只增加被脱敏的字符串集合。**另建议加最小长度门** —— 防超短 secret 把无关输出打成马赛克。

## Task 5: 启动真实受管代理 + CONNECT 策略化（S09 核心）

> **本工作包风险最高的任务。裁定 3 的实现。**

**Files:** Modify `internal/netpolicy/proxy.go`（`:145-147`）、`internal/bootstrap/bootstrap.go`（`:921`）、`internal/shell/factory.go`（`:47-51`）；Test `internal/netpolicy/`

**背景：** 代理写好了却从不启动；子进程拿到的 `http://127.0.0.1:0` 是**伪装成强制的黑洞**。

⚠️ **这是本工作包唯一改变对外可见安全姿态的改动**：从「子进程无网」变成「子进程经受管代理按策略出网」。客观上是**放宽** —— 从「意外的严格」走向「设计的严格」。因此有三条必须钉死的边界。

- [ ] **Step 1: 写三条边界测试（先于实现）**

**断言什么**：
1. **fail-closed 不因启动代理而失效** —— 默认 `Default:""` 下，任意 host 经代理返回 **403**
2. **CONNECT 目标 host 走 `CheckHost`** —— deny 时**不建立隧道**
3. **`PrepareEnv` 剥离继承变量的行为在真 URL 下仍成立** —— 否则父进程的 `https_proxy` 可**影子覆盖**受管代理

**为什么先写**：这三条是放宽动作的安全网。**先有网再跳。**

**预期**：第 2 条编译/运行失败（CONNECT 当前被直接拒绝）。

- [ ] **Step 2: 实现 CONNECT 策略化**

**怎么改**：从 CONNECT 请求行取目标 host，跑 `CheckHost`，通过后**盲隧道**。

⚠️ **禁止 MITM** —— 解密流量会成为**新的 secret 泄漏面**。只做 host 策略判定 + 盲转发。

- [ ] **Step 3: 真正启动代理并接线**

**怎么改**：bootstrap 启动代理并把**真实 URL** 传下去；`shell/factory.go` 不再用假 URL 占位。

⚠️ **`http://127.0.0.1:0` 这类伪装成强制的占位 URL 必须彻底移除** —— 要么真代理，要么**显式无策略**。半吊子比没有更糟：它制造了「有防护」的错觉。

- [ ] **Step 4: 补审计发射**

**背景**：netpolicy 生产代码 slog/audit **零命中**，而验收含「决策入审计」。

**断言什么**：一次「未授权连接失败」的 Decision **进入了审计**。

**为什么重要**：这是纯增量、无沙箱依赖，且是验收明写的一条。
