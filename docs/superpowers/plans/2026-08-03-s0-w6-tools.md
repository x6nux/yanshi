### 跨工具共享根因：生产 Factory 不继承环境变量

`internal/shell/factory.go:51/55` 做 `env = netpolicy.PrepareEnv(spec.Env, proxyURL)`，而 `spec.Env` 是 nil。实测 dump 子进程环境：

```
child env = "HTTP_PROXY=http://127.0.0.1:0\nHTTPS_PROXY=http://127.0.0.1:0\nNO_PROXY=\n"
```

**整个子进程环境只有这 3 条。没有 PATH、没有 HOME、没有 GOPATH/GOMODCACHE。**

⚠️ 这是与 `Cmd`/`Wait` **完全同型**的「fake 比生产更完整」问题，而且**就在同一批测试里**：`internal/tools/git_test.go:60` 的 `realGitFactory` 写的是 `cmd.Env = append(os.Environ(), spec.Env...)` —— **测试替身继承了环境，生产实现没有。**

`netpolicy.ManagedEnv`（`proxy.go:204`，即 `PrepareEnv(os.Environ(), ...)`）**就是为此写的**，却**全仓非测试代码零调用**。

> 💡 这是一条 GOV6 型的「只有定义没有调用点」，但签名不是 `With<X>(ctx,...) context.Context`，**GOV6 抓不到**。可作为治理层的第二条线索。

## 五条裁定

**裁定 1 — `DefaultSecureFactory` 的环境修复归本工作包，与 W1 的新 factory 互不冲突。**
W1 Task 5 新建的是 `SecureLaunchFactory`（实现 `shell.ProcessFactory`，服务 shell v2），并**明确要求不要修改 `DefaultSecureFactory`**（实现 `secproc.Factory`，服务 git/run_tests/github）。**两条路径、两个接口。** 本工作包负责后者。

> 两者都应使用 `netpolicy.ManagedEnv`。若 W1 已抽出共享 helper，**复用它**。

**裁定 2 — `timeout==0` 在构造期 panic，无界必须显式写 `NoTimeout`。**

`0` 在 Go 里最自然的读法是「未设置」，但 `WithTimeout` 解释成「立刻过期」—— **这个语义错配就是根源**。

⚠️ **不能塞一个巨大常数糊过去** —— 那只是把 bug 变成难复现的 bug。

**设计**：
1. 加导出哨兵 `tools.NoTimeout`（建议 `= time.Duration(-1)`）。⚠️ **负值在 `WithTimeout` 下同样立刻过期，所以必须显式分支**
2. `Stream` 在 `g.timeout == NoTimeout` 时改用 `context.WithCancel(ctx)` —— 语义是「只受 turn ctx 约束」，这是**诚实且真实存在**的上界
3. `NewGuardedTool` 对 `timeout == 0` **构造期 panic**
4. **只有 `agent_wait` 该用 `NoTimeout`** —— `streamAgentWait`（`agent_lifecycle.go:109-113`）已支持可选 `timeout` 入参，为 0 时 `Manager.Wait` 阻塞到终态，**外层再套死超时是错的**
5. 其余 7 个都是内存 registry 操作，给 `30*time.Second`

**裁定 3 — `github_*` 的「真实出网」明确记为 W5 依赖，不在本工作包解决。**

实测：`bootstrap.go:918` 传 `ProxyURL: ""`，factory 注入 `HTTP_PROXY=http://127.0.0.1:0`：
```
$ env HTTP_PROXY=http://127.0.0.1:0 gh api rate_limit
  → proxyconnect tcp: dial tcp 127.0.0.1:0: can't assign requested address
$ gh api rate_limit    # 无代理时正常
```

**W6 修完自己三条，`github_*` 仍到不了真实 GitHub，直到 W5 的 S09 起一个真代理。**

**做法**：W6 修工具名 + 退出码降级 + 环境继承，用 **PATH 上的 stub `gh`（生产 factory + 真子进程）** 做端到端验收。⚠️ **`GH1` 翻 `done` 时必须在计划与 `ghSpec` 注释里写死这条残留依赖，不能藏。**

**裁定 4 — `T11` 换数据源，且它不受死代理影响，可独立收口。**
已实测可行替代：`POST https://html.duckduckgo.com/html/` 稳定返回 10 条，`result__a` / `result__snippet` / `result__url` 三个 class 齐全。它走**进程内 `http.Client` + `netpolicy.NewTransport`**，**不走子进程** —— 不受裁定 3 的限制。

**裁定 5 — 四项未复核的必须先重验（Task 9），不得直接采信审计。**
`LSP1` / `C13` / `MCP1` / `V16` 的逐行复核**未完成**。考虑到审计对 W07/DT4/DT5/GH1 的理由**全部**已过时，**直接采信审计的风险不低**。
